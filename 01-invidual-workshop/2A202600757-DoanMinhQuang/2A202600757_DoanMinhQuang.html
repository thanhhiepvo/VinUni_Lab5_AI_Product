Chi tiết 4 path

Happy path (không áp dụng 3 query chuyển tiền)
Ví dụ: "Lịch sử GD tháng 5" → deep link + filter → xong. AI = router read-only.
Low-confidence path — Query 1, 2, 3
AI hiểu intent một phần nhưng hỏi chung chung (STK, NH) hoặc clarify text dài, không list contact / không chip.
Kẹt: User không biết chọn gì tiếp trong chat (#2).
Failure path — Query 1, 2, 3
Sau guidance: "đã ghi nhận" (Q1, Q3) hoặc 3 bước manual (Q2) — đẩy sang app NH/ví ngoài, không pre-fill V-App.
Q1 cuối: đủ 5M + BIDV + STK vẫn không handoff (#3). Q3: reminder + 17:00 bị bỏ.
Correction path — Cả 3 query
User thoát chat → vào Chuyển tiền thủ công → nhập lại amount / recipient / STK → OTP.
Kẹt: Chat không giảm effort, đôi khi tăng (#4). AI không log correction để cải thiện.

3 · Sửa một path yếu nhất (To-be)

Path được chọn

Guidance + Low-confidence + Failure khi user có transaction_intent (chuyển / nạp / thanh toán).

  • Cả 3 query đều rơi path này — ROI cao nhất khi sửa một lần.
  • V-AI vẫn không execute — cải UX bằng handoff, không thêm payment API.
